
`GET /api/transactions`, `GET /api/transactions?category=...`, `GET /api/transactions/:id`.

## Аудит безпеки (практикум 15)

### 1. XSS через innerHTML

Пошук `innerHTML` у проєкті:

| Місце | Що підставляється | Висновок |
|---|---|---|
| `apiList.innerHTML = ''` (3 рази, script.js) | порожній рядок - лише очищення списку | безпечно |
| `toast.innerHTML = ...` (повідомлення про додану операцію) | категорія, введена користувачем | **вразливість**, виправлено |

Решта рендеру безпечна: список операцій, сторінки категорії й статистики рендерить Vue
через `{{ }}` (екранує HTML), секція API будує елементи через `createElement` + `textContent`,
діаграма малює назви через `ctx.fillText` (текст на Canvas, не HTML), посилання на категорії
кодуються `encodeURIComponent`. `v-html`, `insertAdjacentHTML` і `document.write` не використовуються.

**Вразливість.** Повідомлення «Додано витрату ... у категорію «...»» збиралося шаблонним рядком
і записувалося в `innerHTML`. Категорія `<img src=x onerror="alert('XSS')">` виконувалась
як HTML - з'являвся `alert`.

**Виправлення.** Розмітку створює `document.createElement('strong')`, а дані користувача
передаються в `replaceChildren()` рядками - вони стають текстовими вузлами. Той самий рядок
тепер відображається як звичайний текст. Додатково категорія з одних пробілів більше не
зберігається.

### 2. Дані в localStorage / IndexedDB

Зберігаються лише операції: сума, тип, категорія, дата. Паролів, токенів, імен, номерів карток
чи рахунків немає. Водночас суми витрат - фінансова інформація: localStorage та IndexedDB
не шифруються, доступні будь-якому скрипту сторінки і не мають терміну дії. Для навчального
прототипу це прийнятно; у реальному застосунку такі дані варто зберігати на сервері з
автентифікацією, а резервну копію в localStorage (практикум 11) не дублювати.

### 3. Секрети в коді

Реальних ключів і паролів у коді немає: Frankfurter не потребує ключа, власний API працює
без автентифікації.

### 4. HTTPS і сервер

Під час розробки сайт працює на `http://localhost`, що браузери вважають безпечним контекстом.
Для публікації: статична частина - GitHub Pages (HTTPS за замовчуванням), Node.js-сервер -
хостинг з HTTPS (наприклад, Render). Сервер не віддає приховані файли (`.gitignore`, `.git`),
не дає вийти за межі теки застосунку (`../`) і надсилає заголовок `X-Content-Type-Options: nosniff`.
